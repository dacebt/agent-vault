# Notes and documents

Use this path for observations, reference material, and updates from evidence already
in hand. Read the [note template](../../../templates/note.md) for `knowledge/` or the
[document template](../../../templates/doc.md) for a structured reference in `docs/`.
The shared [linking doctrine](../../../reference/linking.md) governs topic connections.

Read the relevant existing topic and its index first. Extend that record when the
content belongs there; choose a descriptive kebab-case filename for a genuinely new
topic. Keep unrelated content and useful history intact when revising a record.
A README update belongs in its existing structure rather than a new templated concept.

Notes use `type: note`; structured references use `type: doc`. Give new concepts a
clear title, one-sentence description, suitable tags, and the template's provenance
fields. Keep YAML values safe. Advance `generated.at` with a timezone-aware timestamp
when a concept changes. Record sources when claims derive from specific artifacts;
add aliases only for names people actually use for the concept. Uncertainty remains
visible in the content rather than becoming a fabricated fact.

Link the concepts this record explains, extends, depends on, or contrasts with, and
name why the relationship matters. Add or update the directory's `index.md` entry;
maintain useful return links from directly related topics. Include every changed
record and index in the scoped durability commit described by capture.

For "update the project docs," use the request to bound which existing records to
read and amend. Incorporate established changes, missing explanations, and decisions
supported by the conversation; use capture's decision path for the latter. This is
not an invitation to audit the whole vault. Systematic truth checking belongs to
refresh, while graph-wide maintenance belongs to weave.
